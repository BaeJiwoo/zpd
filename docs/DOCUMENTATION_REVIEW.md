## 코드에서 확인한 차이

| 우선순위 | 확인한 내용 | 영향과 후속 작업 |
| --- | --- | --- |
| 높음 | 소켓 서버·콘솔 클라의 기본 포트는 `30000`, Unity 매칭 테스트는 `20000` | 기본 설정 그대로는 연결되지 않는다. 실행 안내에 포트를 맞추는 절차를 추가했다. 공통 기본값을 정하고 코드·씬·기본 실행 검증을 함께 수정할 필요가 있다. |
| 중간 | 연결 확인 API의 HTTP 200 본문 스키마가 OpenAPI에 없다 | 명세만으로 `status`, `database`를 알 수 없다. DTO와 응답 타입을 선언하고 다시 생성할 필요가 있다. 생성 결과 일치만으로는 이 누락을 잡지 못한다. |
| 중간 | API 스모크는 경로 노출과 HTTP 503만 확인한다 | DB 정상 연결과 응답 본문은 검증되지 않는다. 새 API를 추가할 때 성공·실패 본문과 데이터 변경 검증을 연결해야 한다. |

## 수정한 표현과 절차

- 시스템 그림은 목표로 하는 논리 배치로 명시했다. 실제 장비 구성·운영 배포·소켓 DB 연결·기획 툴 구현과 구분했다.
- API에는 연결 확인 라우트가 있으므로 '빈 프로젝트', 'HTTP 라우트가 없다', '도메인 라우트'라는 표현을 고쳤다. 로비·아이템·보상·인증은 미구현이다.
- EF Core와 도구 설정은 있지만 엔티티·마이그레이션은 아직 없다고 적었다. 두 서버가 사용할 테이블의 쓰기 주체와 첫 마이그레이션 적용 절차는 후속 설계 항목이다.
- API 라우팅 가이드에 성공 DTO의 명세 반영, 인증과 URL의 구분, 스모크·OpenAPI 검증 범위, DB 없이 명세를 추출하는 조건을 보완했다.
- 루트 빌드·테스트에는 Unity 빌드·플레이 검증이 포함되지 않음을 명시했다. `Contracts` 대상은 TCP 생성 검증이고 HTTP 검증은 `Api` 대상에 있다.
- 서버 명령을 실행할 폴더, 실제 포트와 접속 주소를 바로잡았다. 서버의 모든 IPv4 인터페이스 접속 대기와 클라의 loopback 접속 주소를 구분했다.
- TCP 메시지 번호가 정의돼 있어도 기능이 구현된 것은 아니며, Unity 본문 생성 대상은 현재 `matchmaking.proto`뿐이라고 적었다.
- C++ 서식 명령에서 생성된 메시지·오류 상수를 제외하고, `contracts`의 파일에도 적용할 스타일 경로를 명시했다.
- 솔로 Play 검증은 프로세스 시작 후 별도 결과 파일의 `PASS`/`FAIL`을 확인하도록 보완했다. 이전 테스트 기록과 이번 정적 검토를 구분했다.
- 클라 작업 목록의 무기 구매·교체·시간 기반 강화를 현재 카드 성장·웨이브 기반 강화로 갱신했다. 로비의 로그 중복 방지를 서버의 중복 지급 방지로 읽히지 않게 고쳤다.
- 솔로의 HTTP 전송 코드와 서버의 저장·보상 구현을 구분했다. 현재 라우트가 없어 로컬 API 실행 중에도 요청은 실패한다.
- GitHub 워크플로 설정과 실제 원격 실행·브랜치 보호 적용을 구분했다. bundle 백업은 refs에서 도달 가능한 이력이며 미커밋 파일은 포함하지 않는다고 고쳤다.

## 앞으로 정할 내용

기획 툴은 API를 통해 아이템 정의를 조회·수정하는 흐름으로 문서화했다.
소켓 서버에 변경을 전달하는 방법, 다음 세션부터 적용할지 진행 중 세션에도 적용할지,
아이템 정의와 유저 소유 아이템의 저장 구조는 아직 정해야 한다.
결과 저장·보상 반영의 담당 서버, 인증·권한, 배포 순서도 첫 관련 기능을 구현하기 전에 정한다.
작성할 가이드 목록은 [작업 가이드](guides/README.md)를 따른다.

## 검토 범위와 확인 방법

현재 코드의 경로·라우트·상수·DTO·생성 대상·검증 스크립트를 읽고 문서와 대조했다.
현재 안내 문서 25개의 상대 링크 105개, 코드 블록의 닫힘, PowerShell 예제 15개의 구문을 확인했고 오류는 없었다.
C++ 서식 대상 42개에 생성된 메시지·오류 상수가 포함되지 않는 것도 확인했다. 실제 서식 변경은 실행하지 않았다.
Git diff 공백 검사도 통과했다.
빌드·통합 테스트·Unity Play·실제 MySQL 연결·배포를 이번 문서 검토에서 다시 실행한 것은 아니다.

[이전 소켓 문서](archive/socket-server/README.md)와 [솔로 개선 기록](../client/Docs/SOLO_DEFENSE_REVIEW.md)은
당시의 설계와 검증 기록으로 보존한다. 과거 본문을 현재 구현 설명으로 사용하지 않도록 안내했다.
게임의 전체 동작이나 동시성·보안 결함을 모두 검증한 코드 리뷰를 뜻하지는 않는다.
