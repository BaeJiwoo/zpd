# 작업 가이드

가이드는 실제로 반복할 작업을 기준으로 나눕니다.
파일을 어디에 추가할지, 어떤 순서로 연결할지, 무엇을 확인하면 끝나는지를 적습니다.
시스템 배치는 [루트 README](../../README.md#시스템-배치), 현재 구현은 각 프로젝트 README를 기준으로 합니다.

## 작성 순서

| 순서 | 가이드 | 담을 내용 | 상태 |
| --- | --- | --- | --- |
| 1 | [공통 작업 순서](FEATURE_WORKFLOW.md) | 시작 동작, 담당 시스템, 요청·응답, 데이터 변경, 반영 시점, 완료 기준 | 초안 작성 |
| 2 | [API 라우팅 추가](API_ROUTING.md) | URL·HTTP 메서드, 컨트롤러, DTO, 서비스 등록, DB 연결, 테스트, OpenAPI 갱신 | 초안 작성 |
| 3 | DB 구조·데이터 변경 | 두 서버의 테이블별 조회·수정 주체, 마이그레이션, 초기 데이터, 트랜잭션, 중복 처리, 되돌리는 방법 | 작성 예정: `DATABASE_CHANGES.md` |
| 4 | 인증·권한 추가 | 게임 유저와 기획자 권한, API 인증, TCP 접속 인증, 만료·로그아웃 처리 | 작성 예정: `AUTHORIZATION.md` |
| 5 | 소켓 메시지 추가 | `.proto`, 메시지 번호, 생성 코드, 패킷 분기, 상태 변경, 응답·알림, 클라 처리, 통합 검증 | 작성 예정: `SOCKET_MESSAGES.md` |
| 6 | 클라이언트 기능 연동 | UI 동작에서 요청까지, 로딩·실패·재시도, 응답 반영, 씬 전환, 접속 종료 | 작성 예정: `CLIENT_INTEGRATION.md` |
| 7 | 기획 툴과 아이템 데이터 수정 | 아이템 정의와 유저 소유 아이템 구분, 입력 검증, 미리보기, 저장·반영, 버전·변경 이력, 진행 중 게임 처리 | 작성 예정: `ITEM_TOOL.md` |
| 8 | 실행 환경과 배포 | 개발·테스트·운영 설정, 시스템별 주소·포트, DB 접근 설정, 배포 순서, 호환성, 상태 확인·복구 | 작성 예정: `DEPLOYMENT.md` |

먼저 DB 변경과 인증·권한 가이드를 정리하고, 실제 API와 소켓 기능을 추가하면서 해당 가이드에 예시를 쌓습니다.
기획 툴을 만들기 전에는 아이템 데이터 구조와 수정 내용을 게임에 반영하는 방법을 정합니다.
기획 툴의 프레임워크와 실제 서버 장비 구성은 아직 정하지 않았습니다.

## 가이드에 공통으로 넣을 내용

1. 이 작업을 언제 하는지와 시작 전에 정할 것.
2. 현재 참고할 구현과 추가·수정할 파일 위치.
3. 시스템 사이에 오가는 요청, 응답, 데이터 변경 순서.
4. 실패·중복 요청·연결 종료가 생겼을 때의 동작.
5. 실행할 검증 명령과 직접 확인할 결과.
6. 같이 수정할 명세·문서와 완료 기준.

코드 예시는 현재 구현인지, 앞으로 추가할 예시인지 표시합니다.
아직 만들지 않은 서비스나 테스트가 이미 있는 것처럼 적지 않습니다.
가이드의 절차가 바뀌면 해당 구현과 가이드를 같은 PR에서 수정합니다.
