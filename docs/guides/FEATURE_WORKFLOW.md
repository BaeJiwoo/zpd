# 시스템을 연결해서 기능을 만드는 순서

기능을 추가할 때는 어떤 동작에서 시작해서 어느 시스템을 거쳐 어떤 결과를 만드는지부터 정합니다.
배치는 [루트 README](../../README.md#시스템-배치)를 따릅니다.

## 1. 시작과 결과 정하기

유저나 기획자가 무엇을 하는지, 작업이 끝나면 무엇이 달라져야 하는지 적습니다.
예를 들어 "기획자가 아이템 공격력을 수정하고, 다음 게임부터 수정한 값이 적용된다"처럼 적습니다.
이 예시의 반영 시점은 설명용이며 아직 확정된 정책은 아닙니다.

## 2. 담당 시스템 정하기

화면과 입력, 요청 처리, 게임 판정, 데이터 저장을 각각 어느 시스템에서 처리할지 정합니다.
API 서버와 소켓 서버가 모두 MySQL을 사용할 계획이므로, 변경할 데이터의 쓰기 주체도 정합니다.
두 서버가 같은 결과를 따로 확정하거나 같은 보상을 중복으로 지급하지 않도록 합니다.

## 3. 요청과 데이터 흐름 정하기

호출 주체, HTTP 라우트 또는 소켓 메시지, 입력·출력, 필요한 권한을 적습니다.
조회·수정할 데이터와 저장 후 어느 시스템에 결과를 전달할지도 적습니다.
DB에 저장한 값이 실행 중인 클라나 소켓 서버에 자동으로 반영된다고 가정하지 않습니다.
다음 조회, 새 게임 시작, 별도 갱신 알림 중 언제 읽어 적용할지 정합니다.

## 4. 실패했을 때의 동작 정하기

잘못된 입력, 권한 없음, 대상 없음, 중복 요청, 타임아웃, 접속 종료를 필요한 범위에서 다룹니다.
저장은 됐지만 응답이 끊긴 경우에도 같은 처리를 반복하지 않도록 재시도 기준을 정합니다.
이미 진행 중인 게임에 데이터 변경을 적용할지, 시작할 때 읽은 버전을 유지할지도 정합니다.

## 5. 구현하고 함께 확인하기

통신 계약, 처리하는 서버, 호출하는 클라나 툴을 연결합니다.
정상 동작과 실패 동작을 검증한 뒤 계약·생성 파일·가이드를 함께 갱신합니다.
기능이 여러 프로젝트에 걸쳐 있으면 같은 PR에서 변경 내용을 확인할 수 있게 합니다.
설정은 코드 기본값뿐 아니라 Unity 씬에 저장된 값과 서버 실행 인자까지 확인합니다.
임시 포트로 통과한 통합 테스트와 사용자가 기본 설정으로 실행하는 경로를 각각 확인합니다.

## 작업 시작할 때 적을 내용

아래 항목을 이슈나 작업 문서에 적고 시작합니다.

```text
만들 동작:
시작하는 주체와 입력:
완료됐을 때의 결과:
담당 시스템과 처리 순서:
요청·응답과 필요한 권한:
조회·수정할 데이터와 쓰기 주체:
변경 내용을 게임에 반영할 시점:
실패·중복·재시도 처리:
검증 방법과 완료 기준:
아직 정하지 않은 것:
```

완료 기준에는 "요청을 보냈다"뿐 아니라 저장 결과와 호출한 쪽에 반영된 결과까지 포함합니다.
